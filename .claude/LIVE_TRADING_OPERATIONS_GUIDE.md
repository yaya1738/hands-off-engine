## 🔐 Safety System Architecture

### Three-Layer Safety Gate

**Layer 1: Infrastructure Health Check**
- File: `infra_gate.json` on droplet
- Checks: System health, connectivity, data freshness
- Control: `ho_gate` binary on droplet
- View: Run `hoinfragate.sh` from Termux

**Layer 2: Execution Plan Validation**
- File: `execution_plan.json` on droplet
- Generated by: `ho_executor_plan.py`
- Checks: Position sizes, confidence thresholds, risk limits
- Validation: Executor reflexes (70% confidence min, $100 max position)

**Layer 3: Runtime Safety Checks** (`hoexecsafe.sh`)
```bash
# Hard safety requirements:
1. health.status == "healthy"
2. infra.infra_allow_trades == true
3. gate_blocked == false (in non-DRYRUN)
4. live_enabled == true (for LIVE mode)
```

**Killswitch:**
- Touch `/root/hands-off-out/KILLSWITCH` on droplet
- Instantly blocks all trading
- Check: `killswitch_present` in execution plan


**3. No Orders in Plan**

```bash
# Symptom: mode == "DRYRUN" but should be LIVE
```
