# LLM Integration Overview

## Purpose

The LLM intelligence layer provides AI-driven market analysis for the Hands-Off trading system. It augments the existing Polymarket pipeline with sophisticated probability estimates, confidence levels, and reasoning from state-of-the-art language models.

## Pipeline Flow

### 1. Input: `polymarket-compact.json`

**Location:** `~/hands-off-out/state/polymarket-compact.json`

**Format:**
```json
{
  "markets": [
    {
      "id": "market-001",
      "question": "Will Bitcoin reach $100k in 2025?",
      "category": "crypto",
      "yes_price": 0.62,
      "no_price": 0.38,
      "volume": 500000,
      "closes_at": "2025-12-31T23:59:59Z"
    },
    {
      "id": "market-002",
      "question": "Will the Senate pass the infrastructure bill?",
      "category": "politics",
      "yes_price": 0.55,
      "no_price": 0.45,
      "volume": 100000,
      "closes_at": "2025-03-01T00:00:00Z"
    }
  ]
}
```

**Source:** Generated by `alpha/ho_alpha_polymarket.py` or `termux-hands-off/agent/pm_trim.py`

---

### 2. Processing: LLM Analysis

**Script:** `llm/ho_llm_polymarket.py`

**Steps:**
1. **Load markets** from input JSON
2. **Initialize LLMMarketAnalyst** with DRYRUN mode (default)
3. **For each market:**
   - Select appropriate LLM backend (Claude API, OpenRouter, or fallback)
   - Route to category-specific prompt (politics, crypto, sports, macro, generic)
   - Call LLM API (or simulate in DRYRUN mode)
   - Parse and validate JSON response
   - Fall back to naive model if LLM unavailable
4. **Aggregate results** with metadata

---

### 3. Output: `llm_alpha_report.json`

**Location:** `~/hands-off-out/state/llm_alpha_report.json`

**Format:**
```json
{
  "generated_at": "2025-11-18T12:34:56.789Z",
  "analyst_status": {
    "dry_run": true,
    "has_llm_backend": false,
    "available_backends": [],
    "fallback_enabled": true
  },
  "total_markets": 2,
  "llm_analyzed": 0,
  "fallback_count": 2,
  "markets": [
    {
      "id": "market-001",
      "question": "Will Bitcoin reach $100k in 2025?",
      "category": "crypto",
      "yes_price": 0.62,
      "volume": 500000,
      "closes_at": "2025-12-31T23:59:59Z",
      "llm_analysis": {
        "fair_probability": 68.5,
        "confidence": "medium",
        "edge_bps": 650,
        "reasoning": "Simulated analysis for DRYRUN mode. Market at 62.0%, estimate 68.5%.",
        "action": "buy_yes",
        "backend_used": "claude-api",
        "model_name": "claude-api",
        "prompt_version": "v1.0.0",
        "tokens_used": null
      },
      "analysis_source": "llm"
    },
    {
      "id": "market-002",
      "question": "Will the Senate pass the infrastructure bill?",
      "category": "politics",
      "yes_price": 0.55,
      "volume": 100000,
      "closes_at": "2025-03-01T00:00:00Z",
      "llm_analysis": null,
      "analysis_source": "fallback_naive"
    }
  ]
}
```

**Schema:**

| Field | Type | Description |
|-------|------|-------------|
| `generated_at` | ISO timestamp | When analysis was run |
| `analyst_status` | object | LLM backend availability and mode |
| `total_markets` | integer | Total markets analyzed |
| `llm_analyzed` | integer | Markets analyzed with LLM |
| `fallback_count` | integer | Markets using fallback (no LLM) |
| `markets` | array | Per-market analysis results |

**Per-market schema:**

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Market identifier |
| `question` | string | Market question |
| `category` | string | Market category (crypto, politics, etc.) |
| `yes_price` | float | Current YES price (0-1) |
| `volume` | float | Market volume in USD |
| `closes_at` | string | Resolution timestamp |
| `llm_analysis` | object or null | LLM opinion (null if unavailable) |
| `analysis_source` | string | "llm" or "fallback_naive" |

**LLM Analysis object:**

| Field | Type | Description |
|-------|------|-------------|
| `fair_probability` | float | LLM's estimate of YES probability (0-100%) |
| `confidence` | string | "low", "medium", or "high" |
| `edge_bps` | integer | Edge in basis points vs market price |
| `reasoning` | string | 1-2 sentence explanation |
| `action` | string | "buy_yes", "buy_no", or "avoid" |
| `backend_used` | string | Which LLM backend was used |
| `model_name` | string | Specific model identifier |
| `prompt_version` | string | Prompt template version |
| `tokens_used` | integer or null | Token count (if available) |

## Usage

### Command Line

```bash
# Basic usage (DRYRUN mode, reads from default paths)
python llm/ho_llm_polymarket.py

# Custom input/output paths
python llm/ho_llm_polymarket.py \
  --input ~/hands-off-out/state/polymarket-compact.json \
  --output ~/hands-off-out/state/llm_alpha_report.json

# Limit number of markets (for testing)
python llm/ho_llm_polymarket.py --max-markets 10

# Use speed-optimized backends
python llm/ho_llm_polymarket.py --priority speed

# Enable real API calls (requires API keys)
python llm/ho_llm_polymarket.py --no-dryrun
```

### Python API

```python
from llm import LLMMarketAnalyst
from llm.backend_selector import Priority

# Initialize analyst
analyst = LLMMarketAnalyst(
    default_priority=Priority.QUALITY,
    enable_fallback=True,
    dry_run=True,  # DRYRUN mode
)

# Analyze a single market
market = {
    "question": "Will Bitcoin reach $100k?",
    "category": "crypto",
    "yes_price": 0.62,
    "volume": 500000,
    "closes_at": "2025-12-31",
}

opinion = analyst.analyze_market(market)

if opinion:
    print(f"Fair probability: {opinion.fair_probability}%")
    print(f"Edge: {opinion.edge_bps} bps")
    print(f"Action: {opinion.action}")
    print(f"Reasoning: {opinion.reasoning}")
else:
    print("LLM analysis unavailable, use fallback")
```

## Error Handling & Safety

### DRYRUN Mode (Default)

- **Enabled by default** for safety
- **Simulates LLM calls** without real API requests
- **Returns realistic synthetic responses** for testing
- **No API costs** or rate limiting
- **Logs all operations** for audit trail

### Graceful Degradation

1. **No API keys configured** → Falls back to `analysis_source: "fallback_naive"`
2. **API call fails** → Returns `null` for `llm_analysis`
3. **Invalid LLM response** → Logs error, returns `null`
4. **Malformed market data** → Handles missing fields gracefully

### Validation

All LLM responses are validated against schema:
- `fair_probability` must be 0-100
- `confidence` must be "low", "medium", or "high"
- `action` must be "buy_yes", "buy_no", or "avoid"
- All required fields must be present

Invalid responses are rejected and logged.

## Configuration

### Environment Variables

| Variable | Purpose | Required |
|----------|---------|----------|
| `ANTHROPIC_API_KEY` | Claude API access | Optional (enables Claude backend) |
| `OPENROUTER_API_KEY` | OpenRouter proxy access | Optional (enables OpenRouter backends) |

Without API keys, the system falls back to naive model simulation.

### Backend Priority

Choose backend priority based on use case:

| Priority | Use Case | Backend Selection |
|----------|----------|-------------------|
| `quality` | Best accuracy | Claude API → OpenRouter Claude → GPT-4 |
| `speed` | Low latency | OpenRouter Llama → GPT-4 → Claude |
| `cost` | Minimize spend | Local models → OpenRouter Llama → Fallback |

## Troubleshooting

### LLM analysis always returns `null`

**Cause:** No API keys configured or DRYRUN mode with backend unavailable

**Solution:**
1. Set `ANTHROPIC_API_KEY` or `OPENROUTER_API_KEY`
2. Or use DRYRUN mode (default) for testing without API keys

### "No backends available" warning

**Cause:** API keys not set in environment

**Solution:**
```bash
export ANTHROPIC_API_KEY="your-key-here"
# or
export OPENROUTER_API_KEY="your-key-here"
```

### Invalid JSON in LLM response

**Cause:** LLM produced non-JSON output

**Solution:** Logged and handled automatically. System falls back to `null` analysis.

## Maintenance

### Updating Prompts

1. Edit prompts in `llm/prompt_library.py`
2. Increment `PROMPT_VERSION`
3. Run tests: `pytest tests/unit/test_prompt_library.py`
4. Commit changes

### Adding New Backend

1. Add to `Backend` enum in `llm/backend_selector.py`
2. Add `BackendConfig` to `BACKEND_REGISTRY`
3. Implement API call logic in `LLMMarketAnalyst._call_llm_api()`
4. Update tests

### Monitoring

Check `llm_alpha_report.json` for:
- `llm_analyzed` count (should be high if API keys configured)
- `fallback_count` (should be low if LLM working)
- `analyst_status.available_backends` (should list configured backends)

## Security

### API Keys

- **Never commit API keys** to the repository
- Store in environment variables only
- Use `.env` file with proper permissions (not committed)

### Rate Limiting

- System respects backend rate limits
- Gracefully degrades to fallback on quota exhaustion
- No automatic retry loops (prevents runaway costs)

### DRYRUN Safety

- **DRYRUN mode is default** to prevent accidental API usage
- Must explicitly pass `--no-dryrun` to enable real calls
- All real API calls are logged
